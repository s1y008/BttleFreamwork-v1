§ 03

核心议题 · 段号驱动问题

这一节是整篇文档的核心,按你要求的"原状 / 痛点 / 解决 / 为什么演化"四要素组织。

3.1 原状 · 演化起点是什么样

改造前 · 攻击流程
// 动画师在 AnimationClip 中手动配置 OnSkillCase Event
// 玩家攻击动画的"判定帧"放一个 Event,Function=OnSkillCase, String="10002,0.5,200"

// CombatUnitController.cs - 反射入口
private void OnSkillCase(string args)
{
    int skillId = int.Parse(args.Split(',')[0]);
    var skill = CurCombatUnit.GetSkill(skillId);
    skill.SetSkillCaster(this, m_Target);
    skill.SkillHit();          // → ImmedDamage → OnDamaged → OnAttackEffect(hitEffects[0])
}

// Skill.cs - 受击特效配置
public List hitEffects = new List { 3001, 3002, 3003 };

改造前所有特效都用 hitEffects[0](永远是第 0 个),因为"按段号索引"这件事根本没建模。

✓ 改造前能跑
  • 单段技能:火花能正常播放
  • 伤害计算无问题
  • AnimationClip Event 配置后能触发
✗ 改造前的局限
  • 多段技能全部用同一个特效
  • 刀光(挥刀视觉)和火花(判定视觉)没分开
  • 玩家/技能/段数的乘积增长,工作量爆炸

3.2 痛点 · 哪里不对劲

痛点 01

技能需要"第 1 段火花 + 第 2 段爆炸 + 第 3 段终结"的递进感,但当前所有段共用 hitEffects[0]。

痛点 02

玩家挥刀需要"刀光跟随武器运动",但当前 OnSkillCase 只挂受击特效到敌人身上,玩家身上没有自己的特效。

痛点 03

规模化问题:10 玩家 × 5 技能 × 5 段 = 250 段伤害,每段至少 1 个 Event = 250~500 个 Animation Event需要动画师手动配置。

痛点 04

教学层面:学员改技能必须找动画师改 FBX,改帧时机要重开 Maya/Blender,门槛太高。

"我现在做的游戏又不仅仅是一个玩家一个技能,我要做的游戏有可能有多个玩家。比如我现在有 10 个玩家,每个玩家的技能有 5 个,每个技能有 5 段以上的伤害……你还有没有更好的解决方案?可以加速开发的" — 蔡振立 · 2026-09-12 关键追问

3.3 解决 · 4 轮失败方案的演进

版本方案问题失败原因
v1 Animation Event + 反射 + 计数器自增 自测发现"释放一次技能计数器始终为 1" OnSkillCase 内部多次调用 SetSkillCaster,每次都触发 ResetSegIdx(),计数器永远归零
v2 v1 + isNewExecution 30 帧阈值 实测仍输出 1 段间隔超过 0.5 秒(典型 RPG 技能),isNewExecution 被反复误判成 true,每次都 ResetSegIdx
v3 删除 30 帧阈值,改 Time.time 兜底 3 秒 机制上可行但架构仍有问题 仍依赖 Animation Event,500 个 Event 的规模化问题没解决
v4 AnimatorStateInfo.normalizedTime + FSM.OnUpdate 推进 + CSV 配置驱动 — 验证中 — 无 Animation Event,无反射,无计数器自增。段号由归一化时间跨过配置阈值触发。

v1 失败 · 根因分析

反射入口内部多次调用 SetSkillCaster
// OnSkillCase 内部(简化)
private void OnSkillCase(string args)
{
    int skillId = int.Parse(args.Split(',')[0]);
    var skill = CurCombatUnit.GetSkill(skillId);
    
    // ★ 错误源头:OnSkillCase 内部被调了 3~4 次 SetSkillCaster
    //   每次 SetSkillCaster 又调 ResetSegIdx()
    //   → 计数器永远从 0 开始,自增 1 次后被重置
    skill.SetSkillCaster(this, m_Target);  // 第1次 ResetSegIdx
    skill.SetSkillCaster(this, m_Target);  // 第2次 ResetSegIdx
    // ...
    
    // 最后 BeginNextSegment() 自增 1 → 输出"1"
    skill.BeginNextSegment();
}

v2 失败 · 阈值 bug

30 帧阈值 ≈ 0.5 秒,典型 RPG 段间隔更长
// v2 修复:在 OnSkillCase 入口判断 isNewExecution
bool isNewExecution = skillId != m_LastOnSkillCaseSkillId
    || Time.frameCount - m_LastOnSkillCaseFrame > 30;

if (isNewExecution && m_CurSkill != null)
    m_CurSkill.ResetSegIdx();   // ← 误判时反复归零

m_LastOnSkillCaseSkillId = skillId;
m_LastOnSkillCaseFrame = Time.frameCount;

问题:典型 RPG 技能段间隔 ≥ 1 秒(动画蓄力 + 攻击 + 收招),30 帧阈值让"同一段内的多个反射调用"被误判成"新一轮",每次都归零,BeginNextSegment 永远从 0 → 1。

"段间隔 > 阈值"不是"新一轮执行"的可靠信号。真正的"新一轮"信号是 FSM 状态机的转换点(Attack→Idle)。同一"重置职责"在多处冗余实现 = 必然有 bug。 — 沉淀教训

3.4 解决方案 · v4 最终方案

核心思路 · 三句话
  1. 段号不由 Animation Event 决定,而由 AttackState.OnUpdate 每帧检查 AnimatorStateInfo.normalizedTime 推进
  2. 段数 / 时机从 CSV 读取,策划配表而不是改 FBX
  3. 重置职责唯一化:IdleState.OnEnter 是唯一主重置点,AttackState 只负责推进

v4 完整代码 · AttackState.OnUpdate 推进

CombatStates.cs · AttackState 段号推进
public class AttackState : ICombatState
{
    private const float LEAVE_IDLE_GUARD_SECONDS = 5f;
    private bool _leftIdle;
    private float _elapsed;
    
    // ★ 新增:段号推进字段
    private Skill _currentSkill;
    private int _firedSegIdx;     // 已触发的段号(0 表示尚未触发)
    private int _segCount;        // 本次技能总段数
    private float[] _segTimings;  // 段时机(归一化 0~1)
    private bool _castFired;      // 刀光是否已播(避免重入多次)
    
    public CombatState StateType { get { return CombatState.Attack; } }
    
    public void OnEnter(CombatUnitController owner, object context)
    {
        _leftIdle = false;
        _elapsed = 0f;
        _firedSegIdx = 0;
        _castFired = false;
        _currentSkill = null;
        _segCount = 0;
        _segTimings = null;
        
        // 从 context 拿 skillId,加载技能
        if (context is int skillId && skillId > 0)
        {
            _currentSkill = owner.CurCombatUnit.GetSkill(skillId);
            if (_currentSkill != null)
            {
                _currentSkill.SetSkillCaster(owner, owner.m_Target);
                _segCount = _currentSkill.BaseData.SegTimings?.Length ?? 0;
                _segTimings = _currentSkill.BaseData.SegTimings;
            }
        }
    }
    
    public void OnUpdate(CombatUnitController owner, float deltaTime)
    {
        if (!_leftIdle)
        {
            if (!owner.IsAnimatorInIdleState)
                _leftIdle = true;
            else
            {
                _elapsed += deltaTime;
                if (_elapsed >= LEAVE_IDLE_GUARD_SECONDS)
                {
                    owner.RequestState(CombatState.Idle);
                    return;
                }
            }
        }
        else if (owner.IsAnimatorInIdleState)
        {
            // 动画播完 → 回 Idle (IdleState.OnEnter 兜底 ResetSkillSegIdx)
            owner.RequestState(CombatState.Idle);
            return;
        }
        else
        {
            // ★ 段号推进:normalizedTime 跨过 SegTimings[i] 就触发第 i+1 段
            if (_currentSkill != null && _segTimings != null && _firedSegIdx < _segCount)
            {
                var info = owner.GetCurrentAnimatorStateInfo();
                if (info.normalizedTime >= _segTimings[_firedSegIdx])
                {
                    _firedSegIdx++;
                    owner.TriggerSegmentHit(_currentSkill, _firedSegIdx);
                }
            }
            
            // ★ 刀光特效:在第一段伤害触发前 5% 时播(挂到武器,自然消亡)
            if (!_castFired && _segTimings != null && _segCount > 0)
            {
                var info = owner.GetCurrentAnimatorStateInfo();
                if (info.normalizedTime >= Mathf.Max(0, _segTimings[0] - 0.05f))
                {
                    _castFired = true;
                    _currentSkill.PlayCastEffect();
                }
            }
        }
        
        owner.DoAutoFight();
    }
    
    public void OnExit(CombatUnitController owner)
    {
        _leftIdle = false;
        _currentSkill = null;
        _segTimings = null;
    }
}

3.5 为什么演化 · 三个错误认识

错误认识 01

把"出手特效"等同于"OnSkillCase 同帧的爆发"。其实刀光是挥刀过程的持续视觉,应该挂在武器上跟随运动,在 OnSkillCase 之前的动画预备帧创建。

错误认识 02

给"OnSkillBegin 新增动画事件"的方案时,没考虑 10×5×5=500 个 Event 的规模化问题。任何方案都要先过"规模化压力测试"。

错误认识 03

用"OnSkillCase 同帧干伤害+特效两件事"的耦合设计。判定与表现必须分离,逻辑层不应该关心"刀光要不要现在爆"。

错误认识 04

试图用"30 帧阈值"判断"新一轮执行"。段间隔是动画师决定的,代码层不应该猜。真正的"新一轮"信号是 FSM 状态转换点(Attack→Idle)。

§ 07

教训沉淀 · 给未来的自己

7.1 4 个方法论教训

教训 01 · 用户否定

当用户说"你的方案是错的",先承认错误再追问"你想要的是什么",而不是继续推销原方案。

教训 02 · 现有架构

学员/同事问"怎么做"时,先确认当前架构已有的能力,再决定是补缺还是改架构。

教训 03 · 规模化

用户用"10×5×5"量化痛点时,让规模化问题具象化,比泛泛说"工作量太大"更有力。

教训 04 · 重置职责

同一"重置职责"在多处冗余实现 = 必然有 bug。唯一主重置点原则:IdleState.OnEnter 是唯一主重置点。

7.2 技术层面沉淀

Unity Animation Event 的 4 个坑
  • 反射机制:Event 回调是 Unity 通过反射调用,C# 内 0 调用站点,grep 不到不等于没被调
  • 无法 C# 直接调用:PlayMode 验证前必须确认 Clip 上真的绑了 Event,否则任何"计数器逻辑"都是空跑
  • 命名敏感:Function 名拼写错误会静默失败(不报错),必须严格匹配 C# 方法签名
  • String 参数解析:空 args 会 FormatException,逗号/分号分隔在跨语言解析时容易踩坑
FSM 状态机 vs 协程 · 选型矩阵
维度协程 (IEnumerator)FSM 状态 (OnUpdate)
