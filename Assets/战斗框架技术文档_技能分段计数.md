# 战斗框架技术文档 · 技能分段计数（段索引方案 A）

> **功能**：一个技能动画播放过程中绑定多个动画事件（多段攻击），每段命中时播放各自对应的特效。
> **核心思路**：不改动画事件的参数格式，靠**事件回调顺序**自动计数，用 `OnDamaged` 处的 `SegIdx` 索引 `HitEffect[segIdx - 1]`。
> **状态**：✅ 已落地并实测通过（2026-09-11）
> **涉及文件**：`Skill.cs` / `CombatUnitController.cs` / `CombatStates.cs` / `CombatStateMachine.cs` / `BattleConst.cs` / `NYT.controller`
>
> ⚠ **本文是 2026-09-11「段索引方案 A」的历史快照，不再反映现行代码。** 其后经历多轮演进：
> · v4：把「动画事件自增 `BeginNextSegment`」改为 `TriggerSegmentHit` 显式赋段号；
> · v5 P6/P7：段数与分段效果改从 CSV 的 `SegCount` / `SkillEffectTypes` 读取；
> · v5 P10：受击特效改为**攻击方按段算好后传参**，`attacker.m_CurSkill` 反查与 `CombatUnitController.m_CurSkill` 字段均已删除，
>   段号归零点也从 `IdleState.OnEnter` 迁到 `AttackState.OnEnter`，字段名由 `HitEffect`（列 14）改为 `HitEffectIds`（列 24）。
> **现行机制请看 `战斗框架全链路与数据流转.html`。**

## 1. 一句话原理

`Skill` 上挂一个 1-based 的段计数器 `m_SegIdx`，**每收到一次动画事件 `OnSkillCase` 就 +1**；命中结算时由 `OnDamaged` 读 `attacker.m_CurSkill.SegIdx`，取 `HitEffect[segIdx - 1]`。

计数器的归零点**只有一个**：FSM 从 `Attack` 回到 `Idle` 时触发的 `IdleState.OnEnter`。

---

## 2. 要解决的问题

一个技能动画里可能绑定 N 个 `OnSkillCase` 事件（例如 3 段连击），策划在 `HitEffect` 列表里配了 N 个特效 ID，期望：

| 段 | 期望播放 |
|---|---|
| 第 1 段 | `HitEffect[0]` |
| 第 2 段 | `HitEffect[1]` |
| 第 3 段 | `HitEffect[2]` |

改造前 `OnDamaged` 是**无条件把整个 `HitEffect` 列表逐个播一遍**，所以每次命中都糊一脸特效。

约束：**不能改动画事件的参数**（蔡振立明确要求事件只传 `skillId`）。所以段号不能由动画事件带进来，只能靠代码自己数。

---

## 3. 核心设计决策

### 3.1 计数器放 `Skill` 类，不放 `CombatUnitController`

`Skill` 实例来自 `CombatUnit.GetSkill(id)`（`CombatUnit.cs:243`），返回的是 `m_SkillList` 里的**常驻对象**——同一个 `skillId` 永远是同一个实例。

这个特性同时带来一个便利和一个坑：

- 便利：`OnDamaged` 里只凭 `attacker.m_CurSkill` 就能拿到段号，**不需要把 `segIdx` 沿 `SkillHit → HitTarget → ExecuteEffect → ImmedDamage → OnDamaged` 这 4~5 层方法签名穿透下去**。
- 坑：实例是常驻的，所以 `m_SegIdx` 会**跨释放累加**，必须有人负责归零（见 §3.3）。

### 3.2 为什么不用"时间阈值"判断新一轮

直觉方案是"两次事件间隔超过 X 秒就算新一轮，归零重数"。**这条路走不通**，动作游戏的段间隔可长可短（0.2s ~ 1.5s 都常见），任何固定阈值都会误伤：

- 阈值取小了 → 同一技能的段 2、段 3 被误判成新一轮 → 永远是段 1
- 阈值取大了 → 连放两次技能时第二次接着上一次数 → 段号错位

历史上 v2 就是这么栽的：用 `30 帧(≈0.5s)` 判定"新一次执行"，结果段间隔 0.6s 的技能，每段都被判成新一轮，`BeginNextSegment` 永远从 0 → 1。

### 3.3 ✅ 正确判据：FSM 的状态转换点

**"新一次技能释放" 的唯一可靠信号，是状态机从 `Attack` 回到 `Idle` 的那一刻。**

链路必须是闭合的：

```
Idle ──StarSKill 真正播放动画──▶ Attack ──Animator 播完回到待机──▶ Idle
                                                                   │
                                                     IdleState.OnEnter:
                                                       ResetSkillId()
                                                       ResetSkillSegIdx()
```

两个方向缺一不可：

- `StarSKill` 里必须有 `RequestState(CombatState.Attack)`
- `AttackState` 里必须有"检测到动画播完 → `RequestState(CombatState.Idle)`"

> ⚠️ **这是本项目踩过最深的坑**：只写"转换表里 Attack 无自环，所以每轮必过 Idle"是**不成立的**——因为当时全工程**没有任何地方把状态推成 Attack**，`IdleState.OnEnter` 除了启动那一次之外再也不会执行，所谓"唯一主重置点"形同虚设。

## 4. 数据结构

### 4.1 `Skill.cs` — 计数器本体

```csharp
// Skill.cs:150-159
private int m_SegIdx = 0;                 // 当前段索引(1-based,0 = 未开始)
private float m_LastSegTime = -100f;      // 上次段事件的时间戳(秒)
private const float SEG_TIMEOUT_SECONDS = 3f;  // 兜底:3 秒无新事件强制归零
public  int SegIdx { get { return m_SegIdx; } }
```

```csharp
// Skill.cs:166-186
public int BeginNextSegment()
{
    if (Time.time - m_LastSegTime > SEG_TIMEOUT_SECONDS)
    {
        m_SegIdx = 0;                     // 兜底:跨技能或长时间无事件
    }
    m_SegIdx++;
    m_LastSegTime = Time.time;
    return m_SegIdx;                      // 首次返回 1,第二次返回 2 …
}

public void ResetSegIdx()
{
    m_SegIdx = 0;
    m_LastSegTime = -100f;                // 从 -100 起步,杜绝"刚重置就被超时判据命中"
}
```

> `m_LastSegTime` 初值必须是很小的负数，否则第一段事件会被 `Time.time - (-1) > 3f` 判成超时。

### 5.4 归零：出 Attack

`CombatStates.cs:41-94`：

```csharp
public class AttackState : ICombatState
{
    private const float LEAVE_IDLE_GUARD_SECONDS = 5f;   // 保险丝
    private bool _leftIdle;
    private float _elapsed;

    public void OnEnter(CombatUnitController owner, object context)
    {
        _leftIdle = false;      // 见下方说明,必须两段式判定
        _elapsed = 0f;
    }

    public void OnUpdate(CombatUnitController owner, float deltaTime)
    {
        if (!_leftIdle)
        {
            if (!owner.IsAnimatorInIdleState) _leftIdle = true;      // 阶段一:等它切走
            else
            {
                _elapsed += deltaTime;
                if (_elapsed >= LEAVE_IDLE_GUARD_SECONDS)             // 保险丝
                { owner.RequestState(CombatState.Idle); return; }
            }
        }
        else if (owner.IsAnimatorInIdleState)                          // 阶段二:等它切回
        {
            owner.RequestState(CombatState.Idle);
            return;
        }
        owner.DoAutoFight();
    }

    public void OnExit(CombatUnitController owner) { _leftIdle = false; }
}
```

`IdleState.OnEnter`（`CombatStates.cs:8-13`）：

```csharp
public void OnEnter(CombatUnitController owner, object context)
{
    owner.NavStop();
    owner.ResetSkillId();      // SkillId 清 0 —— 同时掐断"动画自动重放",见 §7
    owner.ResetSkillSegIdx();  // ★ 段计数归零
}
```

**为什么 `AttackState` 要两段式判定（`_leftIdle`）？**

`StarSKill` 里 `SetInteger("SkillId", 10003)` 之后，Animator 并不会立刻切换状态——`Idle` 状态上那条转换带 `m_HasExitTime: 1`（`m_ExitTime: 0.84`），要等 Idle 播到 84% 才真正切进技能状态。这一两帧内 `IsAnimatorInIdleState` 仍然是 `true`。

如果进 Attack 当帧就直接判"回到待机了 → 切回 Idle"，`IdleState.OnEnter` 里的 `ResetSkillId()` 会把 `SkillId` 清 0，**那条还没生效的 Idle → Skill 转换条件就永久不成立了 → 技能动画根本播不出来**。

所以必须：先等它**切走**（`_leftIdle = true`），再等它**切回来**。

## 6. 时序图（3 段技能，连放两次）

```
玩家点普攻
   │
   ├─ IdleState.OnUpdate → DoAutoFight → TryCastSkill → StarSKill
   │     SetInteger("SkillId", 10003)
   │     RequestState(Attack)                        ──▶ IdleState.OnExit / AttackState.OnEnter
   │
   ├─ Animator: 仍在 Idle(等 exitTime) ─ 再过几帧 ─▶ 切进 Skill10003 状态
   │     AttackState.OnUpdate: IsAnimatorInIdleState == false → _leftIdle = true
   │
   ├─ 【事件 1】OnSkillCase("10003")   seg 0 → 1   ─▶ OnDamaged: HitEffect[0]
   ├─ 【事件 2】OnSkillCase("10003")   seg 1 → 2   ─▶ OnDamaged: HitEffect[1]
   ├─ 【事件 3】OnSkillCase("10003")   seg 2 → 3   ─▶ OnDamaged: HitEffect[2]
   │
   ├─ clip 播完 → Animator 沿 exitTime 转换自动回到 Idle 状态
   │     AttackState.OnUpdate: _leftIdle && IsAnimatorInIdleState
   │       → RequestState(Idle)                      ──▶ IdleState.OnEnter
   │                                                      ResetSkillId()      SkillId = 0
   │                                                      ResetSkillSegIdx()  seg = 0
   │
玩家再点普攻
   │
   └─ seg 重新 0 → 1 → 2 → 3          ✅ 不会接着上一轮数成 4/5/6
```

## 7. 这条链路顺带修掉的第二个 bug

动画播完时，`SkillId` 的值还停在 `10003`（最后一次 `StarSKill` 设的）。而 `NYT.controller` 的 `Idle` 状态上挂着一条转换：

```
Idle ──[SkillId == 10003]──▶ Skill10003
```

于是动画一播完回到 `Idle`，这个条件立刻再次成立 → **技能自动重放**，段号继续往上爬。

`IdleState.OnEnter` 里的 `ResetSkillId()` 把 `SkillId` 清 0，转换条件失效，自循环被掐断。这两个 bug 是叠在一起造成"越放越乱"的。

## 9. 复位职责的唯一性

段归零**只有一条路径**：`IdleState.OnEnter → ResetSkillSegIdx()`。

`Skill.BeginNextSegment()` 里的 `SEG_TIMEOUT_SECONDS = 3f` 是**异常兜底**，不承担正常归零职责；`AttackState` 里的 `LEAVE_IDLE_GUARD_SECONDS = 5f` 是**防死锁保险丝**，只在 Animator 始终没切进技能状态时生效。

> **经验教训**：这段功能前后改了三版，每一版都栽在"复位点冗余"上——多道重置点互相打架，比一道点更难查。**"在哪里加新逻辑"之前，必须先确认它的调用频率是「每次」还是「每次新一次」。**

## 10. 兼容性与边界矩阵

| 场景 | `segIdx` | 行为 | 结果 |
|---|---|---|---|
| 单段技能（1 个事件） | 1 | `HitEffect[0]` | ✅ |
| 三段技能（3 个事件） | 1 / 2 / 3 | `HitEffect[0] / [1] / [2]` | ✅ |
| 连放两次（每次均走 Idle） | 0→1→2→3，再 0→1→2→3 | 各自独立 | ✅ |
| Buff Tick 触发的 `OnDamaged` | 0（或他人技能残留值） | 走旧"整列表播放"分支 | ✅ 兼容 |
| `attacker.m_CurSkill == null` | 0 | 走旧分支 | ✅ 不崩 |
| `segIdx > HitEffect.Count`（配置比段数少） | — | 走旧分支 | ✅ 不崩 |
| 超过 3 秒无新事件 | 兜底归零 | 下一次事件从 1 开始 | ✅ 兜底 |
| Animator 异常未切进技能态 | — | 5 秒保险丝强制回 Idle | ✅ 不卡死 |

## 13. 附录：三版弯路复盘

| 版本 | 做法 | 现象 | 根因 |
|---|---|---|---|
| **v1** | `ResetSegIdx()` 放在 `Skill.SetSkillCaster()` | 无论几段，永远只播段 1 | `OnSkillCase` **每次事件**都会调 `SetSkillCaster`（3~4 次），每次都把计数清零，`BeginNextSegment` 之后永远是 1 |
| **v2** | 改在 `OnSkillCase` 入口做 `isNewExecution` 检测（`skillId` 变化 **或** 帧间隔 > 30 帧） | 还是永远只播段 1 | `30 帧 ≈ 0.5s` 的阈值被真实段间隔（0.6s）超过，**每段都被误判成新一轮** |
| **v3** | 删掉阈值检测，改由 `IdleState.OnEnter` 作为唯一主重置点；超时兜底改 `Time.time` + 3 秒 | 单次释放正常，**连放两次后段号错位/特效乱播** | 全工程**没有任何地方** `RequestState(CombatState.Attack)`，状态机始终停在 Idle，`IdleState.OnEnter` 自启动后再没执行过 → 计数跨释放累加，越界后掉进"整列表播放"分支 |
| **v4**（当前） | 补上 `StarSKill → RequestState(Attack)` 与 `AttackState → RequestState(Idle)` 两条边 | ✅ 正常 | — |

**三条可复用的教训：**

1. **"调用频率"必须先确认**——`SetSkillCaster` 看着像"新技能入口"，实际是"每次事件都调"的上下文设置。放重置逻辑前必须分清「每次」和「每次新一次」。
2. **时间阈值不是"新一轮"的可靠信号**——动作游戏的段间隔可长可短，任何固定帧/秒阈值都会误伤。
3. **"转换表保证了 X" 不等于 "运行时真的发生 X"**——v3 的推理"Attack 无自环 ⇒ 每轮必过 Idle"在纸面上成立，但没人推状态机进 Attack，这条边就是死代码。**验证设计假设时，要顺着 `RequestState` 的调用方找一遍，而不是只读转换表。**
