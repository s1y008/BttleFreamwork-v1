为什么旋转需要"4 个数字"？

先聊个本质问题

你肯定转过东西：拧瓶盖、转方向盘、点头摇头。

这些动作背后都是"我绕着一根看不见的轴转了多少度"。

但让计算机懂这件事就麻烦了——机器没有"直觉"，它只认数字。

所以有人发明了欧拉角：3 个数字，分别告诉它在 X、Y、Z 三根轴上各转多少（这章讲）。

但欧拉角有个致命的坑叫万向锁（第三章讲）。

于是 1843 年，一个叫威廉·哈密顿的爱尔兰数学家，把"复数"扩展出了四元数。用 4 个数字描述旋转，绕开了那个坑。这就成了今天 Unity、Unreal、Three.js 等所有 3D 引擎的共同选择。

一个直觉类比：
欧拉角就像让你"前后走→左右转→上抬腿"三步描述朝向——好懂，但遇到特定姿势会卡。
四元数就像让你"绕着某根棍子转一圈"——不那么直观，但什么姿势都不会卡。
会用到的词
轴—— 旋转围绕的那根看不见的"棍子"
角度—— 绕那根棍子转了多少
Pitch/Yaw/Roll
飞机 / 物体的三个旋转维度
万向锁
两个旋转"撞"到同一个方向，导致自由度丢失
四元数
4 个数字编码：1 个"转多少" + 3 个"绕哪根轴"

⚡ 核心一句话

欧拉角对人类友好、对机器坑；四元数对机器友好、对人类反直觉。所以游戏里底层用四元数，给你看时才转回欧拉角。

欧拉角 — 最直观的答案

用 3 个数字描述一个旋转

三个轴各转多少度

欧拉角的思路太简单了：

给一个立方体（或飞机、或人偶），告诉它：

  • Pitch（俯仰） = 绕 X 轴 转多少度。点头、抬头。
  • Yaw（偏航） = 绕 Y 轴 转多少度。左看、右看。
  • Roll（翻滚） = 绕 Z 轴 转多少度。歪头、向左肩翻。
在 Unity 里叫 rotation.x / y / z，或更直观的名字 eulerAngles。
三个 0~360° 的小数，看起来就一句话："在 X 上转 45°，在 Y 上转 30°，在 Z 上转 0°"。很自然，对吧？

✋ 自己拖一下试试：

右边那个立方体，拖三个滑块，它会按你给的欧拉角转。这是 transform.rotation = Quaternion.Euler(pitch, yaw, roll) 在浏览器里的样子（CSS 底层其实也是四元数在算，但我们用欧拉角驱动它）。

万向锁 — 欧拉角的致命陷阱

当两个轴"撞"到同一个方向

先听个故事

想象你在驾驶一架飞机：

你把机头向上抬了 90°（Pitch=90°），机鼻现在朝向天空。

这时你再 "左右摆头"（Yaw）和 "歪脖子"（Roll），会发生什么？

它们变成了一回事。因为你的"头顶上方"方向已经转到"原前后方向"，原本 Y 轴做的动作、Z 轴也能做。反过来也一样。

就像地球仪：你看，从北极方向看下去，转动它只能让球绕一根轴转。不管你怎么转、都少了一个维度。

数字上是什么样子？

如果当前欧拉角是 (Pitch=90°, Yaw=任意, Roll=0)，那么

  • (90°, 30°, 0) 和 (90°, 0°, -30°) 表示同一个朝向！
  • 你想"绕 Y 转 30° 加绕 Z 转 30°"，结果只会变成"绕一根合并的轴转 60°" —
  • 丢失了一个旋转自由度，物体的姿态会发生"凭空抽搐"。
🚨
历史教训：1961 年 NASA 发射水手号探测器时，工程师忘了一个地方用四元数改用欧拉角，飞船在太空中不受控翻滚，任务失败。这是工程史上关于欧拉角最著名的惨案。

四元数 — 数学家的解药

1883 年哈密顿的"复数扩展"

"复数扩展"？别被名字吓到

普通复数是 a + b·i（2 部分）；

四元数是 a + b·i + c·j + d·k（4 部分）。

为了描述一个旋转，Hamilton 弄出了 3 个"虚部" i、j、k，让它们的乘法具有某些特殊性质（i²=j²=k²=ijk=−1）。

但你完全不用记这些规则。
游戏开发者眼里，四元数只有一个意思：一根轴 + 一个角度。

公式登场（极简版）

假设你想"绕轴 (x,y,z) 转 θ 度"，那么对应的四元数是：

q = cos(θ/2) + sin(θ/2)·(x·i + y·j + z·k)

把两边拆开，就是 4 个数字：

w= cos(θ/2)    // "转了多少"的余弦
x= axisX · sin(θ/2) // 旋转轴 X 分量
y= axisY · sin(θ/2) // 旋转轴 Y 分量
z= axisZ · sin(θ/2) // 旋转轴 Z 分量
✨
几何核心："θ 旋转"被悄悄"减半"成 θ/2。为什么？因为四元数里有一半存"角度"、一半存"轴"。下面动图里看更明白。

四元数的"几何大脑"

为什么 w 一定要 cos(θ/2)？

把 4 个数字拼成几何形状

四元数有 4 个数字，描述的是4 维空间里单位球面上的一个点。

听起来吓人。换个角度：

  • 先看 3 维里的复数（2 个数字）：a + b·i 就是平面上一个点，模长 = √(a²+b²)。把模长归一化（= 1），所有"单位复数"画出来就是个单位圆。
  • 把"复数"再加 2 个虚部（j、k），就升到 4 维，单位四元数 = 4 维单位球面。这叫 S³。
关键 Trick：S³ 球面 + 一个特殊乘法规则 → 能精确表示"任意旋转"且不会出现万向锁。
球面没有"退化成直线"的问题，所以旋转也很优雅。

为什么是 θ/2 而不是 θ？

因为四元数乘法有个特性：把"绕某轴转 θ 度的四元数"自己连乘两次，得到的就是"绕同一轴转 2θ 度的四元数"。

也就是说"一个 q"对应"旋转的一半"——用 sin/cos 时自然就要除以 2。

再次直观：从"3 维"角度看

如果我们只看 (x, y, z) 这 3 个数字（单位球的 3D 投影），就能像看"空间方向"一样看旋转轴：

w 接近 1
几乎没转（θ ≈ 0°，sin 接近 0）
w 接近 0
转了近 180°（cos 接近 0）
w = -1
转了 360°，没变（和 q=1 等价！）
xyz 单位长
轴向（在 sin(θ/2)=1 时轴是单位向量）
单位球面上的 q
把 4D 单位球"压"到 3D 看
q (轴投影) · 转 θ
📌 注意：q 和 -q 表示同一个旋转！这是四元数的"双重覆盖"

SLERP — 球面插值的优雅

从 A 姿态到 B 姿态，最自然的走法

最常见的实际问题

游戏里几乎每帧都要做："让我从姿态 A 平滑过渡到姿态 B"。

看起来直接做：

Naïve approachcsharp
// 千万别这样写 transform.rotation = Quaternion.Lerp(A, B, t);

Lerp 就是"线性插值"，把欧拉角当普通数字简单加权平均。问题来了——

Lerp vs SLERP 的几何

把"旋转"画在球面上：

  • Lerp：四元数/欧拉角直接做线性插值，等价于把 A、B 当笛卡尔空间两点，在球内部走直线。这直线穿到外面时，会产生奇怪的"加速—减速—翻转"，且中间姿态会乱跳。
  • SLERP：真正的"球面大圆插值"，沿球面最短弧线走，速度恒定、最自然。
推荐写法csharp
// 球面插值 transform.rotation = Quaternion.Slerp(A, B, t); // 速度由角频率控制（更像动画曲线） transform.rotation = Quaternion.Slerp(A, B, 1f - Mathf.Exp(-angularSpeed * Time.deltaTime));
🛠️
SLERP 公式（极简版）：
q(t) = sin((1-t)·ω)·A + sin(t·ω)·B，再归一化。其中 ω = A 与 B 的夹角。看着复杂，图里看就很清晰。

四元数 vs 欧拉角

它们不是替代关系，是分工关系
对比项 欧拉角 (3 个数) 四元数 (4 个数)
可读性✅ 一眼懂❌ 4 个数字看不出含义
万向锁❌ 90°/270° 时丢自由度✅ 任意姿势无锁
插值⚠ Lerp 会抖、不均匀✅ Slerp 球面大圆平滑
旋转组合⚠ 矩阵连乘乱顺序✅ q1·q2 直接乘
存储✅ 3 个 float4 个 float
多重表示❌ 一个姿态有无数欧拉角⚠ q 和 -q 同姿态（双覆盖）
典型用途编辑器显示、UI 控制底层运算、动画、IK
✅
实践法则：让用户改的用欧拉角（直观）、让计算跑的是四元数（不会崩）。两者随时可以互转： eulerAngles = q.eulerAngles / q = Quaternion.Euler(x, y, z)

Unity 实战代码

战斗框架里也能直接套

1. 绕任意轴转

绕 Y 轴旋转 90°csharp
// 创建"绕 Y 轴转 90°"的四元数 Quaternion q = Quaternion.AngleAxis(90f, Vector3.up); // 让一个物体绕世界 Y 轴旋转 90° transform.rotation = q;

2. 平滑朝向一个目标

SLerp 平滑转向csharp
void Update() { Quaternion targetRot = Quaternion.LookRotation(target.position - transform.position); transform.rotation = Quaternion.Slerp( transform.rotation, targetRot, 5f * Time.deltaTime // 5 rad/s 的角速度 ); }

3. 多个旋转叠加

先 Yaw 再 Pitchcsharp
Quaternion yaw = Quaternion.AngleAxis(yawDeg, Vector3.up); Quaternion pitch = Quaternion.AngleAxis(pitchDeg, Vector3.right); Quaternion roll = Quaternion.AngleAxis(rollDeg, Vector3.forward); // 注意顺序：右乘 = 应用于自身左乘后续旋转 transform.rotation = yaw * pitch * roll;

4. 反向（回退一帧）

q 的逆 = 共轭 = -xyz, wcsharp
Quaternion q = Quaternion.Euler(30, 45, 0); Quaternion inv = Quaternion.Inverse(q); // 数学上的 q⁻¹ Quaternion ident = q * inv; // = (0,0,0,1) 单位元
🎯
应用到本战斗框架：我用四元数搞定"被击飞时斜向击退 + 砸地翻滚 720°"那种复合动画——Quaternion.Slerp(currentHit, fullHit, t) 一行就够；放欧拉角上会瞬间抽搐。

📐 欧拉角

优点：3 个数字、直观、好编辑

缺点：万向锁、插值抖、顺序敏感

用在：编辑器面板、用户输入、网络同步

🌐 四元数

优点：无万向锁、Slerp 平滑、组合优雅

缺点：不可读、q 和 -q 等价（双覆盖）

用在：动画、IK、物理、骨骼、定时插值

一句话口诀：
"看得见的用欧拉角，跑算式的用四元数，要平滑就 Slerp。"
